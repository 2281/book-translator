# План реализации (ROADMAP)

Приложение: Android-читалка книг с переводом слов английский → русский по тапу.
Итоговый результат — установочный `.apk`.

## Принятые архитектурные решения

- **Перевод — полностью оффлайн, формат ONNX.** Модель Helsinki-NLP
  `opus-mt-en-ru` конвертируется в ONNX (у Helsinki-NLP есть готовая
  ONNX-конвертация), выполнение — через ONNX Runtime Mobile для Android
  (`com.microsoft.onnxruntime:onnxruntime-mobile`). TFLite не используем:
  конвертация Marian-трансформера в TFLite существенно сложнее и менее надёжна.
- **Токенизация** — SentencePiece (используется токенизатором opus-mt),
  библиотека `com.google.sentencepiece:sentencepiece`.
- **Форматы книг (по приоритету):** txt, fb2, epub, читаемый pdf (с текстовым
  слоем). djvu — отложен (требует нативной библиотеки).
- **Стек:** Kotlin, Jetpack Compose, Room (каталог), DataStore (настройки).
- Все форматы приводятся к единому внутреннему представлению
  (книга → главы → абзацы → слова), чтобы читалка и перевод работали одинаково.

## Этапы

### Этап 0. Каркас проекта — ✅ готово (14.11.2026)
- Создан Android-проект (Kotlin 2.0.21 + Jetpack Compose, AGP 8.7.3), Gradle 8.10.2 (wrapper).
- Debug `.apk` собирается: `app/build/outputs/apk/debug/app-debug.apk` (~17 МБ).
- Подключены зависимости этапов 1–2: Room, DataStore, Navigation Compose.

### Этап 1. Читалка txt + каталог (MVP без перевода) — ✅ готово (14.11.2026)
- Экран каталога: список книг, добавление txt через системный picker,
  метаданные в Room, файлы копируются во внутреннее хранилище приложения.
  Удаление книги из каталога.
- Экран чтения txt: разбиение на абзацы, прокрутка, читаемый шрифт по умолчанию
  (Serif 18sp).
- Позиция чтения сохраняется для каждой книги (индекс абзаца + смещение).

### Этап 2. Настройки отображения — ✅ готово (14.11.2026)
- Панель настроек (bottom sheet) в экране чтения: шрифт (с засечками / без /
  моноширинный), размер 12–32sp, цвет шрифта (6 вариантов), цвет фона
  (6 вариантов), фоновое изображение из файла (+ сброс).
- Хранение в DataStore, применение на лету с живым превью, настройки
  сохраняются между запусками. Проверено в эмуляторе.

### Этап 3. Оффлайн-перевод слов (ядро) — ✅ готово (14.11.2026)
- Модель `opus-mt-en-ru` конвертирована в ONNX через optimum
  (encoder + decoder), квантована в int8 (137 МБ против 538 МБ fp32),
  лежит в `app/src/main/assets/model/`. Скрипты конвертации — в `tools/`.
- Токенизация — custom ops SentencePiece из onnxruntime-extensions
  (`tok-encode.onnx` / `tok-decode.onnx` с remap'ом id: у opus-mt нумерация
  vocab.json отличается от нумерации внутри .spm). Токенизация совпадает
  с эталонным HF-токенизатором (проверено тестом на ПК).
- `translate/OnnxTranslator.kt` — инференс: токенизация → энкодер →
  жадное декодирование → детокенизация. Интерфейс `Translator` +
  `CachingTranslator` (кэш в Room, таблица `translations`).
- Ускорение декодирования (v0.1.1): KV-кэш — шаг 0 через `decoder_model.onnx`
  (выдаёт present.*, включая кросс-KV энкодера), далее по одному токену
  через `decoder_with_past_model.onnx` вместо перепрогона всей последовательности.
  NNAPI отключён (`USE_NNAPI = false`): без вендорских драйверов ops падали на
  nnapi-reference, что медленнее CPU-ядер ORT; инференс — CPU, 4 потока.
- Читалка: тап по слову → перевод показывается ПОД словом (интерлинер,
  `ui/reader/InterlinearParagraph.kt` — собственная раскладка абзаца на
  TextMeasurer: английский текст не меняется, перевод мелким шрифтом под
  словом/фразой). Повторный тап снимает перевод. (До v0.3.0 слово
  заменялось переводом в тексте; промежуточная плашка «слово → перевод»
  внизу экрана убрана — мешала чтению.)
- Устойчивые выражения (v0.3.0): словарь идиом `assets/idioms.json`
  (~160 выражений с переводом), `model/IdiomDictionary` при тапе ищет
  самое длинное выражение, содержащее слово (точное совпадение словоформ,
  без учёта регистра). Идиома переводится как единая фраза из словаря,
  без вызова модели.
- Проверено в эмуляторе: map → карта, journey → рейс; повторные переводы
  мгновенные (кэш).
- Переводчик — синглтон уровня приложения (`BookTranslatorApp`): модель
  прогревается в фоне при старте и живёт в памяти, пока жив процесс.
- APK вырос до ~290 МБ (модель + decoder_with_past + нативные .so),
  только arm64-v8a и x86_64.

### Этап 4. Форматы книг — ✅ готово (14.11.2026)
1. **fb2** — свой парсер на XmlPullParser (`parse/Fb2Parser.kt`): текст из
   `<body>` (`<p>`, `<v>`, `<subtitle>`; `<empty-line>` — разрыв абзаца),
   название из `<description>/<book-title>`; `<binary>` и служебные body
   пропускаются.
2. **epub** — свой парсер (`parse/EpubParser.kt`): ZIP → container.xml →
   OPF (manifest + spine) → абзацы из XHTML (`<p>`, `<h1>–<h6>`, `<li>`;
   `<head>`/`<script>`/`<style>` пропускаются, HTML-сущности декодируются,
   при битом XHTML — regex-фолбэк). Без сторонних библиотек.
3. **pdf** (читаемый) — `parse/PdfParser.kt` на PDFBox-Android
   (`com.tom-roush:pdfbox-android:2.0.27.0`): извлечение текстового слоя
   через PDFTextStripper, строки склеиваются в абзацы (разрыв — пустая
   строка/конец страницы), переносы слов склеиваются. Скан без текстового
   слоя — понятная ошибка пользователю.
- Импорт в каталоге принимает txt/fb2/epub/pdf (picker `*/*`, проверка по
  расширению). Проверено в эмуляторе на образцах `samples/`: все 4 формата
  открываются, перевод слов работает в любом формате. Версия 0.2.0.
- **Оглавление (v0.4.0):** `BookContent` дополнен списком глав
  (`Chapter(title, paragraphIndex)`). Источники глав: txt — эвристика
  по заголовкам («Chapter …», «Глава …», «Пролог» и т.п., только короткие
  абзацы); fb2 — секции `<section>` верхнего уровня (название из `<title>`);
  epub — документы spine (название — первый `<h1>–<h6>`); pdf — outline
  (закладки документа). В читалке кнопка «Оглавление» (видна, только если
  главы есть) открывает bottom sheet со списком глав, тап прокручивает
  книгу к выбранной главе. Проверено в эмуляторе на txt, epub
  (в т.ч. настоящий Чехов, 1.3 МБ).

### Этап 5. Полировка и релиз
- Обработка ошибок (битые файлы, OOM на больших книгах, модель не найдена).
- Производительность: большие книги, плавная прокрутка, скорость перевода.
- Иконка, имя, версия; подписанный release `.apk`; проверка на реальном устройстве.

## Отложено / за рамками
- djvu — нужна нативная библиотека, отдельная задача.
- Онлайн-перевод как fallback — только если оффлайн окажется неприемлемым.
